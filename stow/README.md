# Adding and managing Stow packages

This directory is the source tree for GNU Stow. Each package is a directory whose contents mirror the path at which its files should appear on the machine. Use the repository wrapper rather than invoking `stow` directly:

```bash
./bin/dotfiles packages
./bin/dotfiles check <package>
./bin/dotfiles link <package>
./bin/dotfiles unlink <package>
```

The wrapper always uses `--no-folding`, runs a simulation before `link`, and targets either `$HOME` or the package-specific target declared in `packages.targets`.

## Package metadata

| File | Purpose |
|---|---|
| `packages.default` | Packages included by `./bin/dotfiles link --all`. Use only portable, safe defaults. |
| `packages.opt-in` | Packages that require an explicit name because they are platform-, application-, or machine-specific. |
| `packages.targets` | Optional package target overrides. Each non-comment line is `package<TAB>path-relative-to-$HOME`. Unlisted packages target `$HOME`. |

Do not list a package until its source directory exists below `stow/`.

## Add an XDG configuration package

For a target such as:

```text
~/.config/bat/config
```

make the source tree match its path relative to `$HOME`:

```text
stow/
  bat/
    .config/
      bat/
        config
```

If the file is already tracked elsewhere in this checkout, use `git mv` so its history is retained:

```bash
cd ~/.dotfiles
mkdir -p stow/bat/.config/bat
git mv config/bat/config stow/bat/.config/bat/config
```

If this should be a portable default, append `bat` to `packages.default`. If it needs explicit user intent, append it to `packages.opt-in` instead:

```bash
printf 'bat\n' >> stow/packages.default
```

Then preflight and apply it:

```bash
./bin/dotfiles check bat
./bin/dotfiles link bat
```

With `--no-folding`, the result is intentionally granular:

```text
~/.config/bat/         # real local directory
~/.config/bat/config   # symlink into ~/.dotfiles/stow/bat/
```

Stow will not replace the application directory with a directory symlink.

## Add a home-directory dotfile

For a target such as `~/.ripgreprc`, place the file directly under the package:

```text
stow/
  ripgrep/
    .ripgreprc
```

Then register and link it:

```bash
printf 'ripgrep\n' >> stow/packages.default
./bin/dotfiles check ripgrep
./bin/dotfiles link ripgrep
```

## Add a package with a nonstandard target

Some applications keep configuration outside the normal `$HOME` or `~/.config` paths. VS Code is an existing example:

```text
stow/vscode/
  settings.json
  keybindings.json
  prompts/
```

Its target is declared in `packages.targets`:

```text
vscode<TAB>Library/Application Support/Code/User
```

The tab is significant; use a literal tab rather than spaces between the package and target path. The target path must be relative to `$HOME` and may not contain `..`.

For an application targeting `~/.some-app`, use:

```text
some-app<TAB>.some-app
```

and arrange `stow/some-app/` relative to that directory. Register special packages in `packages.opt-in` unless they are proven portable defaults.

Before linking, the target directory should already exist if the application owns it. This prevents the dotfiles tooling from inventing or replacing application-managed directories.

## Safely migrate an existing target

Never use `stow --adopt`. It can silently import machine-local files into the repository.

1. Inspect the destination:

   ```bash
   ls -ld ~/.config/bat ~/.config/bat/config
   readlink ~/.config/bat/config
   ```

2. If the target is a confirmed legacy symlink into this checkout, remove only that link after its source has been moved into the Stow package.

3. If the target is a local user-owned file or directory, back it up first:

   ```bash
   backup="$HOME/.dotfiles-backup/$(date +%Y%m%d-%H%M%S)/bat"
   mkdir -p "$backup"
   mv ~/.config/bat/config "$backup/"
   ```

4. Run the package preflight and link commands:

   ```bash
   ./bin/dotfiles check bat
   ./bin/dotfiles link bat
   ```

5. Validate with the application’s normal command, inspect the link, and check the repository:

   ```bash
   ls -l ~/.config/bat/config
   ./bin/dotfiles check bat
   git status --short
   ```

Rollback is package-scoped:

```bash
./bin/dotfiles unlink bat
```

Restore only that package’s recorded backup if needed.

## State, credentials, and generated files

Stow only intentional, portable configuration. Do **not** Stow or commit:

- credentials, OAuth tokens, or private host data;
- sockets, logs, caches, session files, and lock files generated by applications;
- automatic backups or application databases;
- machine-local settings that have not been deliberately reviewed.

Herdr, Karabiner, and GitHub CLI demonstrate the intended pattern: keep the application directory real and local; link only the reviewed configuration files within it. Add repository ignore rules for known generated files as defense in depth.

## Validate changes before review

Run the fake-home regression test and validate the affected package:

```bash
./test/dotfiles-test.sh
./bin/dotfiles check <package>
git diff --check
git diff --cached --check
```

For a new special target, extend `test/fixtures/stow-repository/` and `test/dotfiles-test.sh` so target mapping and `--no-folding` behavior are covered.
